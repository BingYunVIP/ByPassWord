- 首版尝试 240ms 防抖，后尝试在 `disposeVault` flush；QA 真实验证发现 App 未卸载但立即锁定时仍会清除 DEK 导致未保存。因此撤回全部防抖和 flush 改动，最终版恢复 `saveSecurityConfig` 直接调用 `persistSettings()`，没有新增设置保存定时器。此前关于防抖收益和卸载保证的描述作废。

### 可重复的性能与兼容检查

实际执行：`node /tmp/bypw-notification-final-check.mjs`。此临时脚本读取当前真实 `vault.js` 中 `createSecurityConfig`、`folderCounts`、`getFolderCount`，用项目安装的 Vue computed/ref 在 Node 运行，与旧的逐文件夹 filter 算法对照；不使用真实用户数据。

| 条件/检查 | 实际结果 |
| --- | --- |
| 10,000 条目、80 文件夹 + 收藏虚拟夹、8 轮计数读取 | 旧算法 filter 谓词执行 6,480,000 次，新 computed 缓存只遍历条目 10,000 次；总计数完全一致 |
| 上述单次环境计时 | 旧算法 648.34ms，新算法 11.22ms；计时受机器和运行方式影响，只说明此计数操作，不代表整站速度 |
| 缓存失效 | 改变条目 favorite、追加条目后计数正确更新；不存在文件夹返回 0，收藏虚拟夹语义保留 |
| 默认配置/兼容 | 修改新配置不污染默认值；旧设置、部分字段、null/数组嵌套字段均安全合并；无效 publicIpMode 回退 blacklist，whitelist 保留 |
| 保存路径 | 静态确认不存在 settingsPersistTimer，saveSecurityConfig 立即调用 persistSettings |

复现算法：临时脚本生成 10,000 条 Vue 响应式条目，依次为 80 个文件夹和收藏视图计数，重复 8 轮；分别用旧 `.filter()` 和从当前源文件读取的新 computed 实现求和并断言相等，再修改 favorite 和追加条目检查缓存失效。脚本保存在上面的 `/tmp` 路径，可能被系统清理。

限制：未完成整站性能剖析，不声称所有卡顿已消除；最终真实浏览器的立即锁定回归、设置持久化和布局检查交由独立 QA。
