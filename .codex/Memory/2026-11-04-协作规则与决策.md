记录日期：2026-11-04（Asia/Singapore）。来源：用户本次会话的九项规则和更新技能、补齐目录的明确请求。历史偏好及决策保持原路径，见 [索引](../INDEX.md)。

## 项目协作约束

1. 项目回答先核查当前相关代码、配置、Git、日志和服务，明确已验证、推断、未知与建议；旧记录和他人报告不能替代当前证据。
2. 先区分问答、疑惑、故障、审查、Plan、开发、部署、恢复；只读问题不授予修改或 Git 写操作权限。
3. 业务修改前明确范围、可检查验收标准和 Git 保存方式；适用测试未全过不得进入生产备份或部署。
4. 已授权部署的切换前一步生成最新数据库备份，验证可读、非空、权限及 SHA-256；最多保留两份数据备份，新备份验证完整前不删旧备份，失败停止切换。不得为满足数量先删唯一有效恢复点。
5. 部署后检查真实入口、应用与依赖健康，提供真实浏览器验收步骤；用户明确满意/验收后才可请求最终本地 Commit。
6. 仅可按授权本地 Commit；禁止 Push、Merge、修改远程分支。Commit 后按项目规则清理指定缓存及多余备份，保留生产/回退镜像、恢复配置、数据卷、最新备份与证据，记录磁盘前后与线上健康；不能借清理扩大到其他项目资源。
7. 新管理文档入口为项目根 `.codex/`，包含两个入口文档和六类目录；日期命名新子文档，保留历史并建立索引。
8. 主 Agent 管理需求、状态、授权、整合和审查，不编写业务代码；Developer 实现后真实测试并写 Test 报告，全部 Developer 完成后独立 QA 真实测试并留报告。仅工具不支持时按角色串行并如实记录。
9. 每次交付记录未执行测试、失败、限制、待确认与恢复方法；遵循更高优先级平台及系统约束。
