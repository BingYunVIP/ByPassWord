# 页面与路由设计

> 配套：`docs/ARCHITECTURE.md`（安全模型）、`docs/UI-DESIGN-SYSTEM.md`（视觉基准）
> 原则：新增页面必须复用现有设计语言——毛玻璃窗口、`.hig-card-*` 卡片、`rounded-xl` 控件、`spring-btn` 动效、`#007AFF` 主色。

---

## 1. 路由表

| 路径 | 组件 | 守卫 | 说明 |
| --- | --- | --- | --- |
| `/` | — | — | 重定向：已登录 → `/admin`，否则 → `/login` |
| `/login` | `LoginPage.vue` | `guestOnly` | 账号密码 →（可选）2FA |
| `/reset-password` | `ResetPasswordPage.vue` | `guestOnly` | 邮箱验证 → 恢复码 → 新主密码 |
| `/admin` | `AdminPage.vue` | `requiresAuth` | 现有三栏主界面 |
| `/:pathMatch(.*)*` | — | — | 重定向 `/` |

### 1.1 守卫逻辑

```js
router.beforeEach(async (to) => {
  if (!auth.restored) await auth.restore()        // 用 refresh cookie 恢复会话
  if (to.meta.requiresAuth && !auth.isAuthenticated) {
    return { path: '/login', query: { redirect: to.fullPath } }
  }
  if (to.meta.guestOnly && auth.isAuthenticated) return '/admin'
})
```

- 刷新页面时**先恢复会话再放行**，避免已登录用户看到登录页闪一下。
- `redirect` 参数只接受站内相对路径（防开放重定向）。

## 2. 全局状态机

```
        ┌──────────┐  提交邮箱+主密码    ┌──────────────┐  6位TOTP   ┌────────┐
        │ 未登录    │ ─────────────────▶ │ 待二次验证     │ ─────────▶ │ 已解锁  │
        └──────────┘                     └──────────────┘            └────────┘
             ▲                                  │ 恢复码登录               │
             │ 退出/刷新失败/空闲锁定              ▼                        │
             └────────────────────────────── 已解锁 ◀──────────────────────┘
```

| 状态 | 存什么 | 页面 |
| --- | --- | --- |
| 未登录 | 无 token、无密钥 | `/login` |
| 待二次验证 | `challenge`（5 分钟一次性） | `/login` 第 2 步 |
| 已解锁 | access token（内存）+ DEK（内存） | `/admin` |
| 锁定（空闲超时） | 保留 token，清空 DEK | `/admin` + 锁定遮罩（现有） |

> 锁定与退出不同：锁定只需重新输入主密码解 wrappedDek，不需要重新登录。

## 3. `/login` 登录页

### 3.1 布局（单卡片居中，复用 HIG 视觉）

```
┌──────────────────────────────────────────────┐
│              （毛玻璃窗口 hig-window-*）        │
│                                              │
│        ┌────────────────────────┐            │
│        │  [盾牌渐变图标 48px]     │            │
│        │      密 码 库           │            │
│        │  AES-256 · 零知识加密    │            │
│        │                        │            │
│        │  邮箱                  │            │
│        │  [ me@qq.com        ]  │            │
│        │  主密码                │            │
│        │  [ ••••••••••    👁 ]  │            │
│        │                        │            │
│        │  [      解 锁       ]  │            │
│        │                        │            │
│        │  忘记主密码？            │            │
│        └────────────────────────┘            │
│          KDF 进度：正在派生密钥…               │
└──────────────────────────────────────────────┘
```

- 外层：`h-full w-full flex items-center justify-center` + 现有 `macos-bg-light/dark` 壁纸。
- 卡片：`hig-card-light/dark p-8 rounded-2xl w-full max-w-sm space-y-4`。
- 图标：`w-12 h-12 rounded-2xl bg-gradient-to-br from-[#007AFF] to-[#5856D6]` + `verified_user`（与顶栏一致）。
- 输入框：沿用 `rounded-xl border focus:border-[#007AFF] focus:ring-2 focus:ring-[#007AFF]/20`。
- 主按钮：`w-full py-2.5 rounded-xl bg-[#007AFF] hover:bg-[#0062CC] text-white text-xs font-semibold`。

### 3.2 步骤与状态

| 步骤 | 界面 | 错误提示 |
| --- | --- | --- |
| 1. 输入 | 邮箱 + 主密码 | 「邮箱或主密码错误」（不区分，防枚举） |
| 1a. 计算 | 按钮转 loading，文案「正在派生密钥…」 | — |
| 2. 2FA | 6 位验证码输入（大字号、等宽、自动聚焦） | 「验证码错误，还可尝试 N 次」 |
| 2a. 恢复码 | 切换链接「使用恢复码」→ 输入一次性恢复码 | 「恢复码无效或已使用」 |
| 3. 成功 | 跳 `/admin`（或 `redirect`） | — |

- 验证码输入：`text-2xl tracking-widest text-center`，6 格或单输入框均可，`inputmode="numeric"`。
- 失败次数用尽 → 提示「请稍后再试」并禁用按钮 60 秒。
- 首次使用提供「创建密码库」入口（注册），注册后**强制展示恢复码**（下载 / 打印 / 复制），未确认不可进入。

### 3.3 交互细节

- 回车提交；`autocomplete="username"` / `current-password`，方便密码管理器。
- 主密码框默认隐藏，右侧 `visibility` 图标切换。
- 登录过程中禁用表单，防止重复提交。
- 错误用现有 Toast + 输入框红边（`border-rose-500/50`），不弹 alert。

## 4. `/reset-password` 重置页

三步向导（同一路由内切换，进度条 1/3 → 2/3 → 3/3）：

| 步 | 内容 | 校验 |
| --- | --- | --- |
| 1 | 输入注册邮箱 → 发送验证码 | 无论邮箱是否存在都提示"若该邮箱已注册，验证码已发送" |
| 2 | 输入 6 位验证码 + 恢复码 | 验证码 10 分钟内有效；恢复码一次性 |
| 3 | 设置新主密码（≥12 位，二次确认） | 显示强度条；提交后自动登录并跳 `/admin` |

- 用户没有恢复码 → 第 2 步显示明确提示：
  > 「没有恢复码将无法解密历史数据。你可以选择清空密码库重新开始。」
- 本项目**不提供**托管恢复，服务端任何时候都无法解密数据。

## 5. `/admin` 后台主界面

保持现有三栏布局**完全不变**（左栏文件夹/健康度、中栏类型筛选+列表、右栏详情）。新增能力全部落在「安全与设置」弹窗内：

### 5.1 设置弹窗 Tab 调整

| Tab | 变化 |
| --- | --- |
| 登录邮箱与密码 | 增加「账号 2FA」区块（开关、绑定、恢复码、关闭） |
| 选择加密标准 | 不变 |
| 未操作锁定时间 | 不变 |
| **邮箱配置** | 补全：SMTP 主机/端口/账号/授权码/发件人 + 「发送测试邮件」 |
| **备份时间** | 增加「保留时长」下拉 + 「立即快照」+ **「导出备份」「导入备份」两个按钮** |
| IP 登录记录 | 不变 |
| 日志记录 | 不变（含邮件发送、2FA 变更、导入导出审计） |

### 5.2 备份 Tab 线框

```
备份时间与加密快照
┌────────────────────────────────────────────────┐
│ 自动备份    [每日 03:00 ▾]                       │
│ 保留时长    [30 天 ▾]   7/14/30/90/永久          │
│                                                │
│ [ + 立即创建快照 ]   [ 导出备份 ]   [ 导入备份 ]  │
│                                                │
│ 最近备份：2026-11-01 03:00 · 2.4 MB · 保留 30 天 │
└────────────────────────────────────────────────┘
```

### 5.3 导入流程（弹窗内三步）

1. 选择 `.json` 备份文件 → 前端校验 `version` 与字段完整性。
2. 输入**该备份的主密码** → 本地解密 → 显示「文件夹 8 个 / 条目 5 条」。
3. 选择策略：`跳过已存在`（默认）/ `覆盖同 ID` / `全部作为新条目` → 执行 → Toast 汇总结果。

> 导入的条目会用**当前账号的 DEK 重新加密**后上传，不会污染服务端密钥体系。

## 6. 通用状态规范

| 状态 | 规范 |
| --- | --- |
| 加载 | 按钮内 `loading` 文案 + 禁用；页面级用骨架屏或居中 spinner（`animate-spin`） |
| 空态 | 图标 `folder_open` + 一句说明 + 主操作按钮（现有列表空态即范式） |
| 错误 | Toast（`check_circle` 换 `error` 图标 + rose 色）+ 字段红边 |
| 禁用 | `disabled:opacity-40 disabled:cursor-not-allowed` |
| 危险操作 | 二次确认弹窗，按钮用 rose 语义色 |

## 7. 移动端与窄屏

- `/login`、`/reset-password`：`max-w-sm` 自适应，`p-4` 边距，键盘弹出不遮挡按钮。
- `/admin`：现有布局在窄屏会横向压缩；暂不做移动端重构（P7 可选），但需保证**不出现不可点击的溢出**。
